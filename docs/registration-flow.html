Every path to a registered account

Four sign-up methods, one shared ending. Google and Apple prove identity via OAuth, Email and Phone via a 6-digit code — all four then converge on the same Details → Role → complete-profile tail that actually creates the account.

Proving identity, by method

Where each method actually differs — the real routes and files behind each arrow above.

Google
signIn("google")→ /api/auth/google-callback→ /register/google-complete
Pre-fills name + photo. No further verification needed before /register/details.
Apple
signIn("apple")→ /api/auth/apple-callback→ /register/apple-complete→ /register/apple-email
Apple's own id/email goes to appleEmailId, never email — a real one is collected + OTP-verified before Details.
Email
/api/auth/magic-link→ /register/verify→ /api/auth/verify-magic→ /api/auth/resolve-identity
6-digit code, real send via otpService. No name pre-fill.
Phone
/api/auth/phone/send-otp→ /register/verify→ /api/auth/phone/verify-otp→ /api/auth/resolve-identity
Twilio Verify where configured; India (+91) always uses a mocked demo code.

Shared tail — identical for all four

Once identity is proven, every method lands here and finishes the same way.

  1. /register/details — Full Name, Date of Birth, Gender
  2. /register/role — optional role picker, Skip or Continue
  3. POST /api/auth/complete-profile — re-verifies identity server-side, checks for a duplicate email/phone, creates the User document, sets the session cookie
Reflects the current registration journey — see src/app/(auth)/register/ and src/app/api/auth/ in the repo for the underlying code.
